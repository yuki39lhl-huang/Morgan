### 二、还建议优先补的（按重要性）

#### 1. 数据质量与样本量（当前最关键）
- 目标写的是「样本向 200+ 积累中」。建议设定硬门槛：  
  - 至少 150–200 笔**可配对**交易后再做有意义的特征/AI 分析。  
  - 定期跑 `query_db.py summary` + `analyze_closes.py`，把**配对率、漏记率、按 regime/原因的盈亏比**做成周报指标。  
- 继续用 `backfill_orphan_closes.py` 把历史漏记尽量补干净，否则后面统计会偏。

#### 2. 回测与实盘一致性
- 现有 `backtester.py` 仍是短周期、简化版。建议：  
  - 让回测尽量复用 `strategy_layer` 的真实 `calc_score` / `calc_tp_sl`。  
  - 加入资金费率、更真实的滑点、Algo 触发假设。  
  - 做滚动 walk-forward（至少 3–6 个月），看参数稳定性。  
- 否则「Testnet 赚钱」和「策略有 edge」之间还是有鸿沟。

#### 3. 风控与仓位（上实盘前必须单独验收）
- 仍是 100U 基准 × 20% × 10x。100U 实盘容错极低，一次异常就可能大幅回撤。  
- 建议：  
  - 增加「总权益回撤」硬熔断（不只是日亏损）。  
  - 考虑按 ATR/波动率动态调仓位，而不是固定 20%。  
  - 明确「上实盘前杠杆/仓位独立验收」，不要和策略调参绑在一起（README 已写，执行时要守住）。

#### 4. 持仓状态仍用 JSON
- 短期没问题。中期建议：  
  - 要么把活跃持仓也迁到 SQLite（或至少加文件锁/原子写），  
  - 要么保持 JSON，但启动时强制以交易所 API 为真相、JSON 只做本地缓存（你已经在做，继续强化）。

#### 5. AI 部分定位再明确一点
- 现在 AI 是「否决闸门 + 加减分」，很好。  
- 建议把「AI 预测力」做成可量化指标（例如被否决信号的反事实胜率、`ai_score_adjust` 对最终盈亏的贡献），用 `veto_outcomes` 数据说话，而不是感觉。  
- 样本不够前不要急着调 AI 权重。

#### 6. 工程小改进
- README 已经更新了，但部分内部文档（策略 v6.1、SOUL）可能还有旧阈值残留，建议再扫一遍保持同步。  
- `trade_data.db` 不进 git 正确；建议在日志/健康检查里定期报告库大小、配对率、最近 7 天胜率。  
- 单元测试几乎没有，至少给 `trade_db` 的写入/唯一约束/回填逻辑加几个简单测试，防止回归。

#### 7. 上实盘 checklist 再具体化
当前约定已经不错，可以再加：
- 连续 N 天配对率 > 95%
- 最大回撤可控
- 至少 1–2 周模拟盘与归因库数据一致
- 杠杆/仓位压力测试通过

### 三、总体评价与建议优先级

你现在已经从「能跑的规则机器人」进入了**有数据闭环的半量化阶段**，这是正确路径。  
最大瓶颈不再是「有没有 SQLite」，而是：

1. **把样本质量做扎实**（配对完整、漏记少）  
2. **用数据证明 edge 是否存在**（而不是继续调参数）  
3. **风控与仓位为实盘单独过关**

**短期建议行动顺序**：
1. 跑一段时间，盯紧配对率和漏记补全。  
2. 每周固定用分析脚本出一份「按 regime / 平仓原因 / AI 相关」的简报。  
3. 样本到 150–200 笔后再认真做特征归因，决定要不要动权重。  
4. 并行把回测做得更贴近实盘逻辑。  
5. 实盘前单独降杠杆或缩小仓位做压力测试。
