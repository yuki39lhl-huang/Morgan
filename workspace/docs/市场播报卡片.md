# 市场播报卡片 · 数据约定

这次只定整点「市场播报」用哪些数、每项长什么样。HTML 按这份约定画。你点头之前不改飞书推送，也不改开平仓。

开平仓信号卡、周报不在这次里。文末只列它们的边界，避免和整点卡片混在一起。

当前策略是 `rsi_fade`。整点卡片只看已收盘的 1 小时 RSI，不展示旧评分。

## 推送函数本身返回什么

`push_hourly_report(...)` 发给飞书之后，只返回 `true` 或 `false`。`true` 表示飞书收下了这张卡，`false` 表示没发出去。它不把行情再返回给调用方。

卡片上的内容是发出去之前在本地拼好的。下面两层才是设计要用的：

1. 上游接口：币安和本地缓存实际给出的字段。
2. 视图模型：拼完、画卡片之前的那一份结构。HTML 吃这一份。

## 上游接口

币池固定 7 个：BTC、ETH、SOL、BNB、DOT、LINK、XRP。接口返回里其他币丢掉。

| 接口 | 谁在用 | 成功时拿到 | 失败时 |
| --- | --- | --- | --- |
| `GET /fapi/v1/ticker/24hr` | 整点前刷新价格 | 每个币：`price`、`change_24h`、`volume` | 整表为空，沿用内存里已有价格 |
| 测试网 WebSocket `ticker` | 平时写入内存，整点可当底稿 | `price`、`open_24h`、`high_24h`、`low_24h`、`volume`、`change_24h`、`ts` | 该币价格缺失 |
| 测试网 WebSocket `kline_1h`，断线后补一次 REST | RSI 和走势 | 一根 K 线一条数组，见下 | 该币 RSI 显示「缓存不足」，走势不画 |
| `GET /fapi/v2/positionRisk` | 浮动盈亏、持仓块 | 非粉尘仓列表，见下 | 当空列表，浮动改用本地开仓价估算；不能据此当成真的没仓 |
| `GET /fapi/v1/userTrades` | 今日已实现 | 上海自然日内 `realizedPnl` 加总 | 校准失败就用内存里的 `daily_pnl` |
| `GET /fapi/v2/balance` | 只写日志 | USDT `availableBalance` | 不上卡片 |
| 恐惧贪婪 | 调用方传入 `fg` | 一个整数 | 整点卡片不读它 |

24 小时 ticker 用到的原始字段：

- `lastPrice` → `price`
- `priceChangePercent` → `change_24h`
- `volume` → `volume`（卡片不显示）

持仓一条（`positionRisk` 过滤名义低于 5 USDT 的粉尘之后）：

```json
{
  "symbol": "SOL",
  "type": "LONG",
  "entry_price": 70.0,
  "amount": 2.8,
  "unrealized_pnl": 1.0,
  "current_price": 71.0
}
```

`type` 由 `positionAmt` 的正负决定：正数 `LONG`，负数 `SHORT`。`current_price` 用标记价 `markPrice`。`unrealized_pnl` 用 `unRealizedProfit`。

一根已收盘 1 小时 K 线，卡片只用三个下标：

| 下标 | 含义 | 用途 |
| --- | --- | --- |
| 0 | 开盘时间，毫秒 | 排序 |
| 4 | 收盘价 | RSI、走势 |
| 6 | 收盘时间，毫秒 | 丢掉还没收完的那根 |

收盘时间晚于当前时间的那根不进 RSI，也不进走势。Wilder RSI(14) 至少要 16 根已收盘 K 线（周期 14 再加 2）。不够时 `closed_hour_rsi` 返回 `null`。

本地配置，不打外部接口：

- `max_positions`：现在是 4，卡片写成 `持仓数/4`
- `max_positions_per_symbol`：某币为 0 时，RSI 文案后面加「不开仓」。现在 7 个币都是 1，所以正常卡片没有这句
- RSI 阈值写死：≥70、≤30。回到 50 或满 24 小时才平仓，这两条是交易规则，整点卡片不展示

图标来自本地文件 `scripts/assets/coins/{币种}.png`。走势是本地用最近 24 根已收盘收盘价画的 156×44 不透明 PNG。两张图都先上传飞书，换回 `img_key`。上传失败时该图为空，数字照发。

## 视图模型

这是 HTML 要吃的结构。字段名和现在 `build_hourly_coin_cells` 拼出来的一致。

```json
{
  "title": "市场播报",
  "updated_at": "21:00",
  "summary": {
    "realized": 16.27,
    "floating": 0.0,
    "positions": 0,
    "max_positions": 4
  },
  "signal": "无信号",
  "coins": [
    {
      "symbol": "BTC",
      "price": 63858.0,
      "price_txt": "$63,858.00",
      "change_24h": -0.37,
      "rsi": 55.1,
      "rsi_text": "RSI 55.1 · 未触及",
      "touched": false,
      "cache_ok": true,
      "holding": false,
      "no_open": false,
      "closes": []
    }
  ],
  "positions": []
}
```

`signal` 三态：

- 任一币 `touched` 为 true → `"有信号"`
- 每个币都有 RSI，且都没触及 → `"无信号"`
- 有币缓存不足，且没有任何币触及 → `null`，页脚只留更新时间

单币文案：

| 条件 | `rsi_text` |
| --- | --- |
| RSI 为空 | `RSI 缓存不足` |
| RSI ≥ 70 | `RSI 72.0 · 触及 ≥70` |
| RSI ≤ 30 | `RSI 28.4 · 触及 ≤30` |
| 其余 | `RSI 55.1 · 未触及` |
| 该币禁止开仓 | 上面任一句再加 ` · 不开仓` |

价格文案：没有价格写 `—`。价格 ≥ 100 写两位小数并加千分位，例如 `$1,806.27`。低于 100 写四位小数，例如 `$74.8500`。

涨跌：保留两位，带正负号。大于 0 用涨色，小于 0 用跌色，正好 0 写 `+0.00%` 且不着色。缺失写 `—`，不着色。

`closes` 是已收盘 1 小时收盘价，走势最多用最后 24 个。少于 2 个不画线。线的颜色只看这 24 根的第一点到最后一点：最后不低于最初为涨色，否则为跌色。它和 24 小时涨跌可以相反。

持仓块只在 `positions` 非空时出现。一条长这样：

```json
{
  "symbol": "SOL",
  "side": "多",
  "entry_txt": "$70.0000",
  "mark_txt": "$71.0000",
  "pnl": 1.0,
  "pnl_pct": 1.0,
  "pnl_txt": "+1.00 USDT（+1.00%）"
}
```

`side` 只有「多」或「空」。盈亏大于 0 用涨色，小于 0 用跌色，0 不着色。百分比是盈亏除以开仓名义（开仓价 × 数量）。

浮动是这些仓的盈亏加总。有交易所持仓时用接口里的 `unrealized_pnl`；接口没有该币时，用本地开仓价和现价算。已实现是上海时间当天 `realizedPnl` 合计，单位 USDT，保留两位，带正负号。

顶部三格：

| 标签 | 值 |
| --- | --- |
| 已实现 | `+16.27` |
| 浮动 | `+0.00` |
| 持仓 | `0/4` |

币种顺序固定为配置顺序，不按涨跌排序。两列排列，最后一个落单时单独占一行。现在是 7 个币，所以是 3 行两列加 1 行一列。
