## 🔴 08:04 断热点事件 - 严重 Bug

**事件：** Clash 代理断开导致监控进程挂掉，重启时三个持仓被误杀

**亏损：** -9.36 USDT

| 币种 | 方向 | 入场→出场 | 亏损 |
| :--- | :--- | :--- | :--- |
| SOL | SHORT | $77.95 → $78.96 | -2.59 USDT |
| DOT | SHORT | $1.214 → $1.239 | -4.12 USDT |
| BNB | SHORT | $576.48 → $584.12 | -2.65 USDT |

**根本原因：** 重启时代码没有保留本地缓存的真实止损价，而是用当前数据重新计算。如果当前 ATR 变小，重新算的止损价会更近，导致立刻触发止损。

**修复方案：** 修改 `crypto_signal_monitor.py` 第 1764 行附近，重启时优先从缓存读取止损价：

```python
old = old_pos_dict.get(symbol, {})
if old.get('sl_price') and old.get('tp1_price'):
    sl_price = old['sl_price']  # 保留旧缓存
    tp1_price = old['tp1_price']
else:
    tp_sl = calc_tp_sl(entry, direction, {}, {})  # 没有才重新算
```

**状态：** ✅ 已修复并重启

## 💡 核心教训

1. **止损价是核心状态** - 必须持久化，重启时优先恢复而不是重新计算
2. **日期检查很重要** - 跨天重启时必须重置每日统计
3. **已实现盈亏需要持久化** - 每次平仓后立刻保存到状态文件，防止重启丢失
4. **配置要统一** - `.env` 和代码里的 Key 都要更新
5. **代码审查** - 函数不能只有 prompt 没有实际调用
6. **统一重启** - 用 `kj` 命令统一启动所有进程，不要手动 kill 后单独重启
