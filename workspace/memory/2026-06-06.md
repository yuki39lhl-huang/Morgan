## 代码修复：加密货币监控器的孤儿委托清理

### 问题
老公发现"没有持仓怎么还有委托"——Binance 上持仓已平但 Algo 条件单（止盈止损）残留。

### 根因分析
两个核心问题：
1. **孤儿 Algo 单未清理**：多处（启动同步、5分钟 API 同步、need_rebuild）只清本地缓存，不取消 Binance 上的止盈止损单
2. **粉尘仓位误判**：API 返回 0.01 等微量仓位时，代码当作真实持仓反复重建，产生多余委托

### 修改文件

**`scripts/crypto_signal_monitor.py`**：
- 启动同步：新增查询所有 Algo 单，取消不在持仓里的孤儿单
- 5min 同步 `api_count==0`：清空前对旧持仓币种调 `cancel_algo_orders()`
- `need_rebuild` 路径：计算 old- new 币种差集，调用 `cancel_algo_orders()` 清理
- 全局粉尘过滤：所有 `amount != 0` 检查统一加 `abs(amt) * entry_price >= $5.0`
- 共修 12 处

**`scripts/binance_auto_trade.py`**：
- `get_all_positions()`：加粉尘过滤 `abs(amount) * entry_price >= 5.0`

### 验证结果
- 全链路测试通过：开仓 → 委托下发 → 平仓 → 5min 同步自动清理孤儿单
- 测试用例：开 DOT SHORT，手动平仓，monitor 在 5min 同步中自动检测并取消 DOT 的两个 Algo 单
- 日志确认：`🗑️ 清理孤儿 Algo 单：DOT`

## 策略调整：止盈 ATR 动态化

### 背景
三单 SHORT 全吃止盈（SOL +4.12%, ETH +7.21%, LINK ~+4%），但大盘继续暴跌。老公认为固定 4% 止盈在崩盘行情中太死板。

### 老公决策
调整为止盈跟着 ATR 走（与止损同源）：
- 止盈 = `max(4%, min(ATR × 2.0, 15%))`
- 止损新增上限 15%，防极端 ATR 下失控
- 移动止盈三档从固定 `2%/3%/4%` 改为相对于止盈的 `50%/75%/100%`

### 修改文件
**`scripts/crypto_signal_monitor.py`** — 5 处：
1. `calc_tp_sl` 函数：止盈 ATR 动态（保底 4%，上限 15%）
2. `calc_tp_sl` 函数：止损加 15% 上限 `MAX_SL_PCT`
3. CONFIG `trailing_tiers`：绝对百分比 → 相对比例
4. `update_trailing_stop` 函数：适配新格式，从 tp1_price 反推 tp_pct
5. 所有建仓路径：position dict 新增 `tp_pct` 字段
